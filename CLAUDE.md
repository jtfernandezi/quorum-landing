# CLAUDE.md

Guidance for Claude Code working in this repo. Read this before editing.

## What this is

A **concept marketing landing page** for *Quorum* — an agentic stock/investment-trading product:
a team of 13 specialized AI agents sharing one "Market Brain." It is a static demo page, not a
real application. There is no backend, no data, no API.

## The product MVP (`desk/`)

The repo now also contains the first working prototype of the product itself: `desk/` — a
Python paper-trading desk (13 agents, one `brain.json` Market Brain, exactly one LLM call
per brief via the Strategist agent — currently the OpenAI SDK / model set in
`desk/config.json`) with both a terminal CLI and a local web dashboard (`quorum.py serve` →
`desk/dashboard.html`, localhost-only server with Buy/Pass/Trim/Hold/Exit buttons). See
`desk/README.md` for the design rationale and usage. **The desk and the landing page are
separate worlds:** the vanilla-HTML/no-build rules below apply to the landing page files
only, and desk work must never modify `index.html` / `styles.css` / `script.js` (the
dashboard copies the design tokens instead of linking them).

Dashboard specifics worth knowing before editing `desk/dashboard.html` (still a single
file, no build): it is **hash-routed into pages** (Overview / Briefs / Your team /
Positions / Guardrails / Journal / Activity — the `route()` fn + `PAGE_IDS`). The team
page renders "the floor": a radial map with the Market Brain at center and the 13 agents
seated around it. **The floor's "thinking" pulses are evidence, not decoration** — the
server reports which agent is actually executing via `STAGE` in `quorum.py` (`_stage()`
calls placed at real pipeline steps, exposed as `stage` in `/api/state`); idle means no
pulses. Keep that truthful — don't add ambient/fake activity animations. The brain also
persists `last_scan` / `last_check` so Scout and Sentinel can report "I looked and found
nothing." One data gotcha: `data.snapshot()` scores the last *completed* session's volume
when run intraday (partial-bar fix) — don't "simplify" that away.

## Stack & constraints

- **Vanilla HTML + CSS + JS. No framework, no build step, no package manager, no dependencies.**
  Keep it that way unless the user explicitly asks to introduce a toolchain.
- Three source files do everything:
  - `index.html` — all markup. Sections are delimited by `<!-- ===== NAME ===== -->` comments.
  - `styles.css` — design system in `:root` CSS variables, then component styles, then
    animations, then `@media` responsive rules at the bottom.
  - `script.js` — `AGENTS` data array (renders the agent grid), FAQ accordion, mobile nav,
    email capture (`wireCapture`), IntersectionObserver scroll reveal, and the `signalFlow` IIFE
    that draws the animated "How it works" snake.

## How to run / verify

```bash
cd quorum-landing
python3 -m http.server 4321 --bind 127.0.0.1   # then curl/visit http://127.0.0.1:4321
```

There are no tests and no linter. "Verify" = serve it and `curl -s -o /dev/null -w "%{http_code}"`
the page + assets, and grep for the markup you changed. Do not add a test framework unless asked.

## Conventions (match these)

- **Colors/spacing:** use the `:root` variables (`--accent`, `--panel`, `--radius`, etc.). Don't
  hardcode hex values in components.
- **Accent palette:** signal green `--accent`, teal `--accent-2`, violet `--accent-3`,
  danger/red `--danger` (used for risk/bear), gold `--gold` (caution/neutral).
- **Scroll-in animation:** add the `reveal` class to any new block you want to fade up; the
  observer in `script.js` handles it. No extra JS needed.
- **Agents:** never hardcode agent cards in HTML — add/edit entries in the `AGENTS` array in
  `script.js`. The grid (`#agentGrid`) renders from it.
- **New sections:** wrap in `<section>` with a comment banner; inner content in `.wrap`; use the
  existing `.section-head` / `.eyebrow` / `.grad-text` patterns for headings.
- **Responsive:** add breakpoints to the existing `@media (max-width: 980px)` and `720px` blocks
  at the bottom of `styles.css` rather than scattering new media queries.
- **"How it works" signal flow:** the snake/comet in `#stepsGrid` is generated by the `signalFlow`
  IIFE, which **measures live badge positions** and rebuilds on resize — don't hardcode path
  coordinates. The serpentine bottom-row reversal is a `@media (min-width: 981px)` /
  `.steps .step:nth-child(6…9)` block (the `nth-child` is `+1` because the `<svg>` is the first
  child of `#stepsGrid` — keep it first). Straight segments are `L`; only diagonal row-changes
  curve. Badge timing is comet-synced via per-badge `animationDelay`, so don't eyeball delays.
  Keep the `prefers-reduced-motion` branch intact.

## ⚠️ Compliance guardrails — do NOT break these

This page advertises a regulated (trading) product. When editing copy or mock UIs:

- **Never add real or specific backtested/performance return figures** (e.g. "+14.2% CAGR",
  "Sharpe 1.38", "88% returns") to public-facing content. The SEC Marketing Rule restricts
  hypothetical/backtested performance in mass-market retail advertising. Mock UIs that imply
  metrics must show *structure* (e.g. "Max drawdown chart") and carry an `.illus` label.
- **Keep the `.illus` / "Illustrative" labels and `.illus-note` captions** on any mock data
  panels (dashboard, debate, backtest). Don't remove them.
- **Testimonials are placeholders** and labeled as such. Don't present them as real client
  statements. Real testimonials need client-status + compensation disclosure.
- **Preserve the footer risk disclaimer.** Strengthen, don't weaken it.
- Keep the **"research/execution tool, you approve every trade"** framing — it's the deliberate
  legal posture, not just marketing.
- Open branding question: **"Quorum" may conflict** with ConsenSys/JPMorgan's blockchain of the
  same name. Flag, don't silently rename.
